# Runbook: staff accounts and roles

**Worker accounts hold `queue_worker` ONLY.** The unattended queue worker (the Front Door graph) is a system identity. Give it the `queue_worker` role and no other, in any clinic. A worker account that also holds `front_desk` in the same clinic gets the union of both roles' row-level-security policies (permissive policies OR together) and so keeps front desk's direct INSERT on `mpi.identity_tokens` and `mpi.match_candidates`, which is exactly the path migration 0022 closes for the worker alone. Migration 0024 enforces it in the database (a trigger on `iam.staff_roles` refuses a `queue_worker` grant for an account that holds another active role, and the reverse; a worker may hold `queue_worker` in several clinics). A trigger cannot see rows written before it existed, so a read-only check reports old ones: `python scripts/check_worker_accounts.py [--origin live]` (also run by the CI migrate job for live-origin rows) and check [5] of `scripts/verify_app_role.py`. `scripts/seed_dev_staff.py` creates a dev staff account (demo profile, dev project only) and refuses to give a `queue_worker` any other role.

**The front desk supervisor** (`front_desk_supervisor`, migration 0073) is granted by `scripts/seed_dev_staff.py --role front_desk_supervisor` only to an EXISTING account that already holds `front_desk` in the named clinic (checked in the script and by the database's own grant function); never to a new account, never alone. `--dry-run` first.
