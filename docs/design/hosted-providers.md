# Hosted model providers: Gemini (vlm), Jev via OpenRouter (decision), Sarvam (translation)

Decision of the owner, 2026-10-30: hosted providers approved for **SYNTHETIC DEMO use only**. Built behind the gateway; CI never calls a real provider.

## The rules this build enforces (each has a test in `tests/test_providers.py`)
- **Every registry row is `synthetic_only`.** `config/demo-providers.yaml` is refused whole if any row says anything else. **BUILD-SPEC.md §16.5 still forbids a hosted row from ever being `phi_approved`** ("models that touch patient data run locally"); changing that needs a new, explicit decision and a new register entry, not a config edit. A free-tier row is `synthetic_only` by definition.
- **The gateway keeps its data-policy filter.** A PHI request is never offered to these rows (`NoApprovedRoute`); `GatewayVision` sends PHI unless the deployment is demo + `synthetic_only`; `JevAdapter` refuses a PHI request itself.
- **Explicit timeouts**, from the spec's starting budgets (§16.1): vision 60 s per page (via `vlm_row`, required, no default), hosted LLM 20 s, Sarvam 5 s. Connect is 5 s everywhere; redirects are never followed.
- **Keys only from env names** (`GEMINI_API_KEY`, `OPENROUTER_API_KEY`, `SARVAM_API_KEY`), never logged, never in an error message, never in `ci.yml` (guard test).
- **A required per-role daily spend ceiling with NO default** (`CAREFLOW_SPEND_CEILING_VLM_USD`, `_DECISION_USD`, `_TRANSLATION_USD`). In-memory, as decided (`RoleDailyCeilings`; a restart resets the day). An ordinary call that would pass it raises `SpendCeilingReached`, which the callers already turn into a visible hold or a manual task; the safety class is **never** budget-limited and its spend is still counted. A paid row must carry a non-zero price, otherwise its ceiling could never bite.
- **A provider is built only when every gate holds** (`careflow/provider_setup.py`): not CI; profile `demo` + `CAREFLOW_DATA_POLICY=synthetic_only`; the key; a `CAREFLOW_<PROVIDER>_VERIFIED` date (the day you ran the live check) that is not in the future; the role's ceiling. A missing gate is a named reason, never a crash and never a guess.
- **What consumes the providers (2026-11-14):** only the DEMO Front Door, behind one more switch, `CAREFLOW_DEMO_REAL_MODELS` (off by default; section below), and the demo script. Nothing else sends a page or a text to a hosted provider. Reply interpretation is NOT wired to a real model. (The durable spend ledger now exists: `PostgresSpendLedger`, migration 0016, used when a worker identity is configured.)
- **Red flags first.** The vision output is text read from an image: untrusted, screened by the deterministic rules before any other model call (CLAUDE.md rule 2). An empty transcription is a failure, never "clear". Translation is decorative; the native Tamil red-flag rules run on the original text regardless.

## Appendix B findings (from the providers' current documentation, NOT yet confirmed by a real call)
- **Jev is a router model, not a "decisions" endpoint.** OpenRouter documents `typesafe/jev-router` on the ordinary `/api/v1/chat/completions` endpoint with a `jev-router` plugin; it picks a downstream model per request and returns no calibrated probabilities. The spec's Appendix B line ("a decisions endpoint, distinct from /chat/completions") does not match. The adapter therefore asks for strict-JSON `{choice, confidence}` and spreads the confidence like the `llm_fast` fallback; the result is never calibrated and nothing may auto-approve on it. Because the router forwards the text to a model it chooses, the register entry says so. **The spec text is not edited here (rule: spec wording changes are asked first); this note is the record. Decision for the owner: keep Jev as a synthetic-only convenience engine, or drop it for `llm_fast` alone.**
- Gemini: `generateContent` REST, `x-goog-api-key`, `inline_data` image part, `usageMetadata.promptTokenCount/candidatesTokenCount`.
- Sarvam: `POST /translate`, `api-subscription-key`, `mayura:v1` input limit 1,000 characters, answer `translated_text`; billed per character.
- Prices in `config/demo-providers.yaml` are **placeholders** (labelled): confirm them against each pricing page. Free-tier limits are unconfirmed.

## The opt-in live check (yours to run; CI never does)
`uv run python scripts/provider_live_check.py --provider gemini|jev|sarvam --yes-synthetic` sends ONE synthetic request, prints what the service did (HTTP outcome in fixed words, answer key names, whether the usage fields exist, elapsed time), and tells you whether to record the `CAREFLOW_<PROVIDER>_VERIFIED` date. It reads only the repository's `.env`, refuses under CI or outside demo + `synthetic_only`, and never prints a key. For Gemini, `--image` takes a DUMMY image you made yourself.

## Known limits, stated (found by the compliance review; accepted for a synthetic demo)
- **"Synthetic" is a declared label, not an inspection.** Nothing looks at the content. What stops patient text reaching a hosted adapter is: the deployment gate (demo + `synthetic_only`), the gateway's data-policy filter, and each adapter's own refusal of a PHI-labelled request (`JevAdapter`, `SarvamTranslation`; `TranslationRequest.data_class` is required with no default; `GatewayVision` sends PHI unless the setup says otherwise). A caller that mislabels real text as synthetic defeats all of them; the only feature wired to a provider is the demo Front Door below.
- **The ceiling does not see the provider's bill.** A free-tier row is never skipped for spend and records zero, so the VLM ceiling cannot bite on it. If the Gemini key sits on a project with billing ON, real charges are invisible to the ceiling: keep billing OFF for that project (the only control). Spend is recorded only after a successful call, so a billed-but-rejected reply (bad JSON from the router, a timeout the provider still charged) is not counted; concurrent calls can each pass the check before any is recorded, so the overshoot is bounded by concurrency times one call's cost; with no `estimate` (which `GatewayVision` always passes) a paid row's check is only "already at the ceiling". All of these favour a small, synthetic demo and are not acceptable for clinical use.
- **`Gateway.role_ceilings` is optional** (None means no per-role check); `provider_setup` always supplies it.
- **Demo spend is tagged `origin=test`**, so a dashboard counting `live` spend does not include it.
- **Jev's `model_id` is a router, not a pinned model:** the downstream model varies per request, against the spirit of a pinned model id (spec 5.1). Acceptable for synthetic demo only; the owner confirms.
- **Gemini free-tier terms:** unpaid use of the Gemini API may let Google use submitted content to improve its products. Fine for synthetic data; one more reason no real page goes there.
- **Incomplete output is a failure:** the Gemini adapter accepts only `finishReason` STOP (a cut-off page would let the rules screen half a letter). Missing usage counts are estimated HIGH; thinking tokens count as output.
- **What the live check does and does not prove:** it calls the application's own adapter with a dummy page (required for Gemini), a 1,000-character text (Sarvam), and prints the downstream model Jev chose. It does NOT verify prices or rate limits (Appendix B): read them on the pricing pages. The VERIFIED date is a bare assertion by the owner; re-run the check after any change to an adapter.
- **The vision text is screened by the rules before any other model call** (the wiring below keeps the unchanged Front Door order: transcription, then the deterministic rules, then everything else). `tests/test_demo_real_models.py` proves the order with fake providers and the real graph; it has not had a separate security review.
- **Jev's outputs are never evidence (owner decision 2026-10-30).** Its downstream model is not pinned and varies per request, so nothing it says may be used as evidence for acceptance, gold-set, calibration or golden-input work. `careflow.adapters.decision.NOT_EVIDENCE_ENGINES` / `counts_as_evidence(result)` is the filter that code must apply; `tests/test_providers.py::test_jev_is_refused_outside_the_demo_profile_and_its_output_is_never_evidence` proves it, and proves Jev is not built under any profile but demo with `synthetic_only`. It stays a synthetic-only convenience engine.
- **One-time exception recorded (2026-10-30):** the backend session regenerated `frontend/src/shared/api/schema.d.ts` once (`npm run gen:api`, no hand edits) on PR #14's branch because the checked-in schema was stale against `openapi.snapshot.json`. This does not change the rule that the backend session does not touch `frontend/`.

## Update 2026-11-14 (b): the three providers in the demo flow (synthetic only, every output a suggestion)
**Switch:** `CAREFLOW_DEMO_REAL_MODELS=on` (exactly `on`, `1`, `true` or `yes`), and ONLY with profile `demo`, `CAREFLOW_DATA_POLICY=synthetic_only` and the demo Front Door on (`CAREFLOW_DEMO_PHASE3`). Code: `careflow/demo_real_models.py`; the app wires it at start-up (`careflow/app.py`) and `scripts/demo_real_models.py` runs it once by hand. **A missing key, verified date, ceiling, cap or gate keeps that stage a fake and says why in the log and in the script's printout. It never crashes and never guesses.**

| Stage | Real part | What stays fake |
|---|---|---|
| 1 Text | a stored PDF with a text layer is read locally; a scan or photo is transcribed by **Gemini through the gateway** (durable spend ledger, daily ceiling, per-run cap). This is the one step allowed before the rules (spec 5.2, 10.4). An empty or failed transcription is a hold, never "clear". | with no Gemini route the fictional letter is made up from the document id, as before |
| 2 Rules | the unchanged deterministic red-flag rules, on that text, before any other model. A flagged letter ends there with the nurse task and **no other model is asked**. | |
| 3 Identity | a regular expression (not a model) reads `PATIENT: <name>, DOB <date>` with a verified quote for each claim | |
| 4 Proposal | **Jev via OpenRouter through the gateway** is asked which fictional demo card fits the MASKED letter; its answer only moves that card first in a triage proposal that **waits for a person** (shadow mode: nothing is applied; no training label comes from it; Jev's output is never evidence) | the cards are `demo-synthetic-card-A/B`: no clinical card exists. With no Jev route, or when it cannot answer, the fake order stays and a person still decides |
| 5 Draft | **Sarvam** translates an invented, labelled DEMO DRAFT sentence into Tamil as a suggestion (`suggest_translation`). Nothing is stored or sent. | |

**Limits, stated.** (a) Sarvam sits behind the in-memory per-role daily ceiling AND, since migration 0086, its spend is recorded in the durable ledger (role `translation`) when the request names the clinic; a call whose spend cannot be recorded fails visibly. (b) A document the demo seed wrote has no stored file: with the switch on, running one fails visibly (a dead-letter task for a nurse) instead of inventing a letter; only a canary's fabricated letter is still made up. (c) "Synthetic" is still a declared label, not an inspection. (d) The decision stage learns the clinic from the extractor's memo of the masked-letter digest, because the retriever port is not told the clinic; a letter whose clinic is not known gets no model call. (e) No route exposes the translation draft: it is a function and a line in the script.

**Run it once:** `docs/first-run-guide.md`, section "Optional: one dummy letter through the real models". The script prints only metadata: stage, real or fake, status, seconds, cost, whether the rules fired, the order the stages ran in, and the proposal id.
